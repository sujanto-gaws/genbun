# Template System Guide

This guide explains how to customize genbun's output using the external template system.

## Overview

genbun uses external template files to generate Go models. This allows you to customize the output without modifying the source code. Templates are stored in a directory and loaded at runtime.

## Template Directory Structure

```
templates/
├── model.tmpl          # Main template (assembles all parts)
├── header.tmpl         # Package header and imports
├── struct.tmpl         # Struct definition with fields
├── relations.tmpl      # Relationship fields
├── methods.tmpl        # Helper methods
└── model_with_hooks.tmpl  # Example with lifecycle hooks
```

## Configuration

### Via YAML Config

```yaml
templates:
  path: templates  # Directory containing template files
```

### Via CLI Flag

```bash
genbun generate -T /path/to/custom/templates
genbun generate --templates ./my-templates
```

### Environment Variable

```bash
export GENBUN_TEMPLATES_PATH=/path/to/templates
genbun generate
```

## Template Files

### 1. model.tmpl (Main Template)

This is the entry point that assembles all other templates:

```go
{{- template "header" . }}
{{- template "struct" . }}
{{- template "relations" . }}
{{- template "methods" . }}
```

### 2. header.tmpl (Package Header)

Generates the file header, package declaration, and imports:

```go
// Code generated by genbun. DO NOT EDIT.
// Generated at {{ .GeneratedAt }}
{{- if .Comment }}

// {{ .Comment }}
{{- end }}

package {{ .PackageName }}
{{- if .HasTime }}

import (
	"time"
)
{{- end }}
```

### 3. struct.tmpl (Struct Definition)

Generates the struct with database fields:

```go
// {{ .ModelName }} represents the {{ .TableName }} table.
{{- if .Comment }}
// {{ .Comment }}
{{- end }}
type {{ .ModelName }} struct {
{{- range .Fields }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- if .Comment }}
	// {{ .Comment }}
{{- end }}
{{- end }}
}
```

### 4. relations.tmpl (Relationship Fields)

Generates relationship fields (BelongsTo, HasMany, ManyToMany):

```go
{{- range .Relations }}

	// {{ .Comment }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
```

### 5. methods.tmpl (Helper Methods)

Generates helper methods like TableName:

```go

// TableName overrides the default table name.
func (m *{{ .ModelName }}) TableName() string {
	return "{{ .TableName }}"
}

{{- if .HasRelations }}

// GetRelations returns all relation names for this model.
func (m *{{ .ModelName }}) GetRelations() []string {
	return []string{
{{- range .Relations }}
		"{{ .Name }}",
{{- end }}
	}
}
{{- end }}
```

## Template Variables

The following variables are available in templates:

### ModelTemplate

| Variable | Type | Description |
|----------|------|-------------|
| `.PackageName` | `string` | Go package name |
| `.TableName` | `string` | Database table name |
| `.ModelName` | `string` | Go struct name |
| `.Fields` | `[]ModelField` | Database column fields |
| `.Relations` | `[]ModelField` | Relationship fields |
| `.Comment` | `string` | Table comment |
| `.GeneratedAt` | `time.Time` | Generation timestamp |
| `.HasTime` | `bool` | True if any field uses time.Time |
| `.HasRelations` | `bool` | True if model has relationships |

### ModelField

| Variable | Type | Description |
|----------|------|-------------|
| `.Name` | `string` | Field name (camelCase) |
| `.Type` | `string` | Go type |
| `.Tag` | `string` | Struct tag |
| `.Comment` | `string` | Column comment |
| `.IsPrimary` | `bool` | True if primary key |
| `.IsNullable` | `bool` | True if nullable |
| `.IsRelation` | `bool` | True if this is a relationship field |

## Template Functions

Custom functions available in templates:

| Function | Description | Example |
|----------|-------------|---------|
| `toLower` | Convert to lowercase | `{{ toLower "UserID" }}` → `userid` |
| `toUpper` | Convert to uppercase | `{{ toUpper "user_id" }}` → `USER_ID` |
| `title` | Title case | `{{ title "user" }}` → `User` |
| `camelCase` | Convert to camelCase | `{{ camelCase "user_id" }}` → `UserId` |
| `snakeCase` | Convert to snake_case | `{{ snakeCase "UserId" }}` → `user_id` |
| `comment` | Format comment | `{{ comment "user table" }}` → `// user table` |
| `plural` | Pluralize word | `{{ plural "User" }}` → `Users` |

## Creating Custom Templates

### Example 1: Add Lifecycle Hooks

Create `templates/model_with_hooks.tmpl`:

```go
// Code generated by genbun. DO NOT EDIT.
// Generated at {{ .GeneratedAt }}

package {{ .PackageName }}
{{- if .HasTime }}

import (
	"context"
	"time"
)
{{- else }}

import (
	"context"
)
{{- end }}

// {{ .ModelName }} represents the {{ .TableName }} table.
type {{ .ModelName }} struct {
{{- range .Fields }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
{{- if .Relations }}
{{- range .Relations }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
{{- end }}
}

// TableName overrides the default table name.
func (m *{{ .ModelName }}) TableName() string {
	return "{{ .TableName }}"
}

// BeforeInsert hook
func (m *{{ .ModelName }}) BeforeInsert(ctx context.Context) error {
	// Custom logic before insert
	return nil
}

// BeforeUpdate hook
func (m *{{ .ModelName }}) BeforeUpdate(ctx context.Context) error {
	// Custom logic before update
	return nil
}
```

### Example 2: Add JSON Tags

Modify `templates/struct.tmpl` to include JSON tags:

```go
type {{ .ModelName }} struct {
{{- range .Fields }}
	{{ .Name }} {{ .Type }} {{ .Tag }} `json:"{{ .Name | toLower }}"`
{{- end }}
}
```

### Example 3: Add Validation Tags

```go
type {{ .ModelName }} struct {
{{- range .Fields }}
{{- if not .IsNullable }}
	{{ .Name }} {{ .Type }} {{ .Tag }} validate:"required"
{{- else }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
{{- end }}
}
```

### Example 4: Add GORM-style Tags

```go
type {{ .ModelName }} struct {
{{- range .Fields }}
	{{ .Name }} {{ .Type }} {{ .Tag }} gorm:"column:{{ .Name }}"
{{- end }}
}
```

## Using Custom Templates

### 1. Copy Default Templates

```bash
# Copy default templates to your project
cp -r /path/to/genbun/templates ./my-templates
```

### 2. Modify Templates

Edit the template files to add your customizations:

```bash
# Edit struct template to add JSON tags
nano my-templates/struct.tmpl

# Add custom methods
nano my-templates/methods.tmpl
```

### 3. Generate with Custom Templates

```bash
# Using CLI flag
genbun generate -T ./my-templates

# Using config file
# Edit genbun.yaml:
# templates:
#   path: ./my-templates

genbun generate
```

## Template Best Practices

### 1. Use Whitespace Control

Use `{{-` and `-}}` to control whitespace:

```go
{{- if .HasTime }}

import (
	"time"
)
{{- end }}
```

### 2. Check for Empty Slices

Always check if slices are empty before ranging:

```go
{{- if .Relations }}

// Relations
{{- range .Relations }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
{{- end }}
```

### 3. Use Conditional Imports

Only add imports when needed:

```go
{{- if .HasTime }}

import (
	"time"
)
{{- end }}

{{- if .HasRelations }}

import (
	"github.com/uptrace/bun"
)
{{- end }}
```

### 4. Add Comments for Relations

Always include comments to document relationships:

```go
{{- range .Relations }}
	// {{ .Comment }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
```

## Troubleshooting

### Template Not Found

**Error:** `template directory not found`

**Solution:**
- Check template path is correct
- Use absolute path if relative path fails
- Verify templates directory exists

```bash
# Check if templates exist
ls -la /path/to/templates/

# Use verbose mode to see path
genbun generate -v -T /path/to/templates
```

### Template Parse Error

**Error:** `failed to parse templates`

**Solution:**
- Check template syntax (matching `{{` and `}}`)
- Ensure all template names match (e.g., `header` vs `Header`)
- Validate Go template syntax

### Missing Variables

**Error:** `can't evaluate field`

**Solution:**
- Check variable names are correct (case-sensitive)
- Verify struct fields exist in ModelTemplate
- Review template variable documentation

## Advanced Examples

### Example: Add Soft Delete Support

Create `templates/soft_delete.tmpl`:

```go
// DeletedAt supports soft delete pattern
type DeletedAt struct {
	time.Time
	IsZero bool
}

// {{ .ModelName }} represents the {{ .TableName }} table.
type {{ .ModelName }} struct {
{{- range .Fields }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
	DeletedAt *time.Time `bun:"deleted_at"`
}

// IsDeleted checks if model is soft deleted
func (m *{{ .ModelName }}) IsDeleted() bool {
	return m.DeletedAt != nil
}
```

### Example: Add Audit Fields

```go
type {{ .ModelName }} struct {
{{- range .Fields }}
	{{ .Name }} {{ .Type }} {{ .Tag }}
{{- end }}
	CreatedAt time.Time `bun:"created_at" json:"created_at"`
	UpdatedAt time.Time `bun:"updated_at" json:"updated_at"`
	CreatedBy string    `bun:"created_by" json:"created_by"`
	UpdatedBy string    `bun:"updated_by" json:"updated_by"`
}
```

### Example: Add GraphQL Tags

```go
type {{ .ModelName }} struct {

	{{ .Name }} {{ .Type }} {{ .Tag }} graphql:"{{ .Name }}"
{{- end }}
}
```

```go
{{- end }}

```

## Migration from Embedded Templates

If you were using genbun before external templates:

1. **Default Behavior**: If no template directory exists, genbun falls back to embedded templates
2. **Opt-in**: External templates are only used when the template directory exists
3. **Gradual Migration**: You can customize templates one at a time

```bash
# Old way (still works - uses embedded templates)
genbun generate

# New way (uses external templates)
genbun generate -T ./templates

# Mix and match - customize specific templates
genbun generate -T ./my-custom-templates
```

## Template Inheritance

Templates can include other templates:

```go
{{- template "header" . }}

type {{ .ModelName }} struct {
{{- template "fields" . }}
{{- template "relations" . }}
}

{{- template "methods" . }}
```

This allows you to create modular, maintainable templates.
